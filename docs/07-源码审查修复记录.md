## 一、账号隔离与凭证清除（高）

### 问题

**① 清除数据不彻底**

`store.tsx` 的 `resetAll` 只清了 IndexedDB：

```typescript
for (const store of [...]) await idb.clear(store);
setOidcTokens(null);   // 只清了内存
```

但 `oidc.ts` 把令牌存在 `localStorage`：

```typescript
localStorage.setItem('memo-reader.oidc.tokens.' + tokens.sub, JSON.stringify(tokens));
```

**结果**：点「清除本机所有数据」后，OIDC 令牌依然留在浏览器里，`listStoredAccounts()` 还会列出已"删除"的账号。

**② Token 模式没有独立身份**

```typescript
// maimemo.ts 原代码
return {
  id: todayKey(connector.kind),      // 'token' 或 'oidc'
  accountId: connector.kind,          // ← 只有两种值
};
```

所有 Token 用户共用 `accountId = 'token'`，换 Token 后仍看到前任的数据。

**③ 比审查报告更严重的问题**

`store.tsx` 写入的是 `oidc:<sub>`：

```typescript
accountId: `oidc:${sub}`,    // 'oidc:12345'
```

但 `fetchTodaySnapshot` 写的是 `'oidc'`。

**保存用 `oidc|2026-10-28`，查询用 `oidc:12345|2026-10-28`** —— 永远命中不了缓存，每次都要重新拉。

### 修复

**① `oidc.ts` 新增 `clearAllStoredTokens()`**

```typescript
export function clearAllStoredTokens(): number {
  let removed = 0;
  const keys: string[] = [];
  for (let i = 0; i < localStorage.length; i += 1) {
    const key = localStorage.key(i);
    if (key?.startsWith(TOKEN_KEY_PREFIX)) keys.push(key);
  }
  for (const key of keys) {
    localStorage.removeItem(key);
    removed += 1;
  }
  sessionStorage.removeItem(PENDING_KEY);   // 未完成的授权流程也丢弃
  return removed;
}
```

**② `store.tsx` 的 `resetAll` 三步走**

```typescript
// ① 先尽力撤销服务端授权（失败不阻断）
if (oidcTokens) {
  try { await revokeTokens(oidcTokens); } catch { /* 网络失败也继续 */ }
}
// ② 清 localStorage / sessionStorage
clearAllStoredTokens();
// ③ 再清 IndexedDB
for (const store of [...]) await idb.clear(store);
setKnownAccounts([]);   // 已保存账号列表也要清空
```

`logoutMaimemo` 也加了同样的双保险。

**③ `MaimemoConnector` 加 `accountKey()`**

```typescript
export interface MaimemoConnector {
  /** 稳定的本地账号标识，用于数据隔离 */
  accountKey(): string;
  ...
}
```

**TokenConnector**：用 FNV-1a 指纹，不暴露原文

```typescript
function fingerprint(token: string): string {
  let h = 2166136261;
  for (let i = 0; i < token.length; i += 1) {
    h ^= token.charCodeAt(i);
    h = Math.imul(h, 16777619);
  }
  return (h >>> 0).toString(36);
}

accountKey(): string {
  if (!this.token) return 'token:anonymous';
  return `token:${fingerprint(this.token)}`;   // 换 Token 即换账号
}
```

**OidcConnector**：与 store 层保持完全一致

```typescript
accountKey(): string {
  const sub = this.tokens.sub;
  return sub ? `oidc:${sub}` : 'oidc:unknown';
}
```

**④ `store.tsx` 新增 accountId 自动同步**


## 二、AI 选词校验逻辑错误（高）

### 问题

`validate.ts` 第 32-68 行本意是检测越界选词，但：

```typescript
const known = new Set(picks.map((p) => p.word));   // known = 全部 picks 的词

const outside = out.picks.filter(
  (p) => allowSet.size > 0 && !allowSet.has(p.word) && !known.has(p.word)
  //                              out.picks 就是 picks
  //                              → p.word 必然在 known 里
  //                              → 这个条件恒为 false
);

if (outside.length === out.picks.length) {   // 永远不成立
  out.summary += '（注意：模型给出的词与当日词表匹配度较低）';
}
```

**这是彻底的死代码，越界检测从未生效。**

同一函数还有：`articleCount` 直接采信 AI 声明值，与实际 `articles.length` 可能不一致。

### 修复

重写 `validateSelection`，补上五项检查：

**① 越界检测（修正实现）**

```typescript
const outsidePicks = allowSet.size > 0
  ? picks.filter((p) => !allowSet.has(p.word))
  : [];
const outsideRatio = picks.length ? outsidePicks.length / picks.length : 0;

// 越界词记入 dropped，并在 summary 里给出明确警告
if (outsidePicks.length) {
  const list = outsidePicks.slice(0, 8).map((p) => p.word).join('、');
  warnings.push(`有 ${outsidePicks.length} 个词不在今日词表内（${list}）`);
  for (const p of outsidePicks) {
    dropped.push({ word: p.word, reason: '不在今日词表内' });
  }
}
if (outsideRatio >= 0.5) {
  warnings.push('模型给出的词与当日词表匹配度较低');
}
```

**② picks 去重**

```typescript
for (const item of asArray(obj.picks)) {
  const word = asString(item.word).toLowerCase();
  if (seen.has(word)) {
    dropped.push({ word, reason: '重复选词，已去重' });
    continue;
  }
  seen.add(word);
  picks.push({ word, role, reason });
}
```

**③ targetWords 必须来自 picks，且不跨篇重复**

```typescript
const assigned = new Set<string>();
for (const w of asArray<string>(a.targetWords)) {
  const word = asString(w).toLowerCase();
  if (!seen.has(word)) continue;      // 不是选中的词，丢弃
  if (assigned.has(word)) continue;   // 已经在别的文章里用过
  assigned.add(word);
  targetWords.push(word);
}
```

**④ articleCount 以实际篇数为准**

```typescript
const sliced = articles.slice(0, 3);
const articleCount = sliced.length;   // 不再采信 obj.articleCount

const declared = Number(obj.articleCount);
if (Number.isFinite(declared) && declared > 0 && declared !== articleCount) {
  warnings.push(`模型声明 ${declared} 篇，实际规划 ${articleCount} 篇`);
}
```

**⑤ 未被分配的词补进最后一篇**（避免浪费）

```typescript
const leftover = picks.map((p) => p.word).filter((w) => !assigned.has(w));
if (leftover.length && articles.length) {
  const last = articles[articles.length - 1];
  for (const w of leftover) {
    if (last.targetWords.length >= MAX_WORDS_PER_ARTICLE) break;
    last.targetWords.push(w);
    assigned.add(w);
  }
}
```

**没有改回固定选词算法** —— AI 依然自主决定选词，程序只负责校验与纠偏。

## 四、中断恢复的费用提示（中高）

### 问题

**① 措辞不准确**

`Generate.tsx` 第 303-306 行写着"不会重复计费"，但实际：

- 已完成阶段：不会重发 ✓
- **正在执行但未完成的阶段：需要重新发送，会再次产生费用** ✗

**② 流式响应缺少读取超时**

```typescript
// post() 的 timer 在返回 res 时就 clearTimeout 了
} finally {
  clearTimeout(timer);      // ← 定时器在这里没了
}

// 读流循环没有任何超时保护
for (;;) {
  const { value, done } = await reader.read();   // ← 网络卡住就永远等
}
```

`post()` 的超时只覆盖到"拿到响应头"，进入流式读取后完全裸奔。

### 修复

**① 措辞改准**

```tsx
<p className="meta stage__footnote">
  生成时请尽量保持页面在前台——切到其他 App 后 iOS 可能暂停网络请求。
  回来点「继续」会从<b>已完成的阶段</b>接着走，这些阶段不会重复请求、不会重复计费；
  但若中断时某个阶段正写到一半，该阶段需要重新发送，<b>可能会再次产生这部分费用</b>。
</p>
```

**② 流式读取加空闲超时**

```typescript
const STREAM_IDLE_TIMEOUT = 45_000;

for (;;) {
  let idleTimer: ReturnType<typeof setTimeout> | undefined;
  const idle = new Promise<never>((_, reject) => {
    idleTimer = setTimeout(() => {
      reject(new AppError('deepseek',
        `流式响应中断：连续 ${STREAM_IDLE_TIMEOUT / 1000} 秒没有收到新数据，请检查网络后重试本阶段`));
    }, STREAM_IDLE_TIMEOUT);
  });

  let read: ReadableStreamReadResult<Uint8Array>;
  try {
    read = await Promise.race([reader.read(), idle]);
  } catch (err) {
    try { await reader.cancel(); } catch { /* ignore */ }   // 卡死时主动断开
    throw err;
  } finally {
    if (idleTimer) clearTimeout(idleTimer);
  }

  const { value, done } = read;
  if (done) break;
  ...
}
```

### 修复

```typescript
/* ④ 生成任务里嵌入的文章副本与题目 */
const tasks = await idb.all<GenerationTask>('tasks');
for (const t of tasks) {
  const hadArticle = (t.articles ?? []).some((x) => x.id === article.id);
  const hadQuestions = Boolean(t.questions?.[article.id]);
  if (!hadArticle && !hadQuestions) continue;

  const next: GenerationTask = {
```

本轮修复**没有改动整体架构**：

- 仍然是纯前端（IndexedDB + GitHub Pages）
- 仍然没有后端数据库、任务队列、云端会话
- AI 选词、文章写作、命题、质检仍然是独立阶段，各自结构化输出

修改集中在：`validate.ts`（校验）、`pipeline.ts`（编排）、`oidc.ts` / `store.tsx` / `maimemo.ts`（账号）、`deepseek.ts`（网络）、`Library.tsx` / `Result.tsx` / `Quiz.tsx` / `Generate.tsx`（交互）。
