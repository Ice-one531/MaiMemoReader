## 一、墨墨开放 API

### 1.1 认证

两种方式，本项目的 `src/api/maimemo.ts` 用同一个 `MaimemoConnector` 接口封装：

| 方式 | 凭证 | 适用 |
| --- | --- | --- |
| 个人 Token | `Authorization: Bearer <token>` | 立即可用，适合自用 |
| OIDC 授权 | `access_token`（PKCE / 授权码换取） | 需要先创建应用并审核 |

Token 获取入口（官方文档给定）：

1. 墨墨 App → 我的 → 更多设置 → 实验功能 → 开放 API
2. <https://open.maimemo.com/open/api/v1/tokens/openapi>

### 1.2 本项目实际使用的接口

Base：`https://open.maimemo.com/open`（测试环境为 `https://open-dev.maimemo.com/open`）

| 方法 | 路径 | 请求体 | 响应关键字段 |
| --- | --- | --- | --- |
| POST | `/api/v1/memo/study/get_study_progress` | `{}` | `progress.finished`、`progress.total`、`progress.study_time`（毫秒） |
| POST | `/api/v1/memo/study/get_today_items` | `{ limit: 1000 }` | `today_items[]`：`voc_id`、`voc_spelling`、`order`、`first_response`、`is_new`、`is_finished` |
| POST | `/api/v1/memo/study/query_study_records` | `{ limit, next_study_date:{start,end}, tags, as_count }` | `records[]`、`count`（本项目暂未用于主流程） |
| GET | `/api/v1/memo/vocabulary?spelling=apple` | 无 | `voc.id`、`voc.spelling` |

`first_response` 枚举（对应 `StudyResponse`）：
`FAMILIAR` 认识 / `VAGUE` 模糊 / `FORGET` 忘记 / `WELL_FAMILIAR` 熟知 / `CANCEL_WELL_FAMILIAR` 取消熟知。
本项目只消费前四个；这是**单词级**的当天首次反馈，不是完整记忆模型数据。

### 1.3 关键约束（决定了产品设计）

1. **没有日期参数**：接口语义恒为「今天」。跨日期调度因此不做，只围绕单日数据工作。
2. **当天未在 App 内初始化就拿不到数据**：官方原文「如果当日未打开 App 进行初始化则无法准确计算总数 / 无法获取」，并要求在 App 中开启自动同步。UI 在拿到 0 个词时给出这条提示，而不是报「接口错误」。
3. **公测状态**：官方明确「公测期间不保证可用性和可能随时调整」。所以数据层做了字段可选、空数组降级、错误分类，不把 `total` 当唯一真值。
4. **频控**：10 秒 20 次 / 60 秒 40 次 / 5 小时 2000 次（背单词侧）。本项目一次同步只发 2 个请求，且不在轮询里重复拉取。
5. **只读**：`add_words`、`advance_study` 等写接口一律不用，只申请只读权限。

### 1.4 错误响应格式

实测（无效 Token）：

```json
{"errors":[{"code":"common_unauthorized","msg":"Authorization failed","info":""}],"success":false}
```

404 路径：`{"errors":[{"code":"common_not_found","msg":"Resource or Api not found","info":""}],"success":false}`

`src/lib/errors.ts` 依据 `status` + `errors[0].code` 给出中文解释与处理建议，并标注「可安全重试 / 重试可能重复计费 / 不要重试」。

## 二、墨墨 OIDC 事实核对

从发现文档实测得到的字段：

| 项目 | 值 |
| --- | --- |
| issuer | `https://accounts.maimemo.com/oidc` |
| authorization_endpoint | `https://accounts.maimemo.com/oidc/auth` |
| token_endpoint | `https://accounts.maimemo.com/oidc/token` |
| userinfo / me | `https://accounts.maimemo.com/oidc/me` |
| end_session | `https://accounts.maimemo.com/oidc/session/end` |
| revocation | `https://accounts.maimemo.com/oidc/token/revocation` |
| PKCE | `code_challenge_methods_supported: ["S256"]` |
| token 端点认证方式 | `client_secret_basic / post / jwt / private_key_jwt / none` ← 含 `none`，公开客户端可用 |
| 支持的 scope | `openid`、`profile`、`email`、`phone`、`product`、`third_identity`、`social`、`offline_access` |
| id_token 签名 | `RS256`、`ES256` |

实现要点（`src/api/oidc.ts`）：

- 授权码 + PKCE（verifier 48 字节随机 → S256 challenge），`state` 与 `nonce` 都校验；
- 待完成上下文存 `sessionStorage`，10 分钟过期，`state` 不匹配直接拒绝；
- 换到的令牌按 `sub` 存 `localStorage`，提前 60 秒视为过期并用 `refresh_token` 续期；
- 登出调用 revocation，失败也照常清本地；
- 回调地址取 `location.origin + pathname`（不含 hash 与 query），GitHub Pages 子路径下同样正确；
- **注意**：id_token 的签名在本项目里不做本地验签（浏览器端没有可信 JWKS 固定策略时意义有限），令牌只经由 TLS 直接从 token 端点取得，`sub` 仅用于本地账号隔离。

## 三、跨域（CORS）实测结论

用 `curl` 在本地环境直接观察响应头。**这一步不能只看服务端是否 200，必须看浏览器能不能读到。**

### 3.1 墨墨开放 API

预检（Origin 换成任意第三方域名）：

```
OPTIONS https://open.maimemo.com/open/api/v1/memo/study/get_study_progress
Origin: https://yg-user.github.io
Access-Control-Request-Method: POST
Access-Control-Request-Headers: authorization,content-type

HTTP/1.1 204 No Content
access-control-allow-origin: https://yg-user.github.io
access-control-allow-methods: GET, HEAD, POST, DELETE, OPTIONS
access-control-allow-headers: Authorization, Content-Type
vary: Origin, Accept-Encoding
```

→ 预检**回显任意 Origin**，说明网关层对预检放行。

实际请求（无效 Token）：

```
POST https://open.maimemo.com/open/api/v1/memo/study/get_study_progress
Origin: https://yg-user.github.io
Authorization: Bearer invalid_token_test

HTTP/1.1 401 Unauthorized
content-type: application/json
（没有 access-control-allow-origin）
```

404 路径同样**没有** `access-control-allow-origin`。

**结论（重要）**：墨墨的错误响应不返回 CORS 头。于是浏览器里：

- Token 正确 → 若 200 响应带 CORS 头，前端可正常读取（**该成功路径需要真实 Token 才能最终确认，本报告不假装已验证**）；
- Token 错误 / 权限不足 / 接口 404 → 浏览器一律表现为 `TypeError: Failed to fetch`，与「跨域被拦」「网络断开」无法区分。

产品上的应对：

1. 文案不谎称"Token 错误"，而是并列列出三种可能，并指向连接测试；
2. 提供可选的 Cloudflare Worker 中继，由中继补 CORS 头，从而把真实状态码透给前端；
3. 所有墨墨请求都带 30 秒超时与结构化错误，避免静默失败。

官方文档另有一句关键限制：「应用审核通过和主页地址的域名会被允许跨域请求开放 API」。也就是说个人 Token 模式的跨域放行并非官方承诺的能力，**这正是必须保留中继方案的原因**。

### 3.2 墨墨 OIDC 端点

```
OPTIONS https://accounts.maimemo.com/oidc/token
Origin: https://yg-user.github.io
→ 204，access-control-allow-origin: https://yg-user.github.io，access-control-max-age: 3600

POST https://accounts.maimemo.com/oidc/token（缺 code）
→ 401，且同样带 access-control-allow-origin + access-control-expose-headers: WWW-Authenticate
```

→ **令牌端点的成功与错误路径都允许跨域**，公开客户端 PKCE 在浏览器里可用。

### 3.3 DeepSeek

```
OPTIONS https://api.deepseek.com/chat/completions
Origin: https://example.github.io
Access-Control-Request-Headers: authorization,content-type

HTTP/1.1 200 OK
access-control-allow-origin: https://example.github.io
access-control-allow-credentials: true
access-control-allow-headers: authorization,content-type
access-control-allow-methods: POST
```

错误路径（无效 Key）：

```
POST /chat/completions → 401
access-control-allow-origin: https://yg-user.github.io（存在）
{"error":{"message":"Authentication Fails, Your api key: ****alid is invalid ...","type":"authentication_error"}}
```

→ **DeepSeek 浏览器直连可用，且错误信息可读**，因此 401/402/429 等都能准确翻译成中文提示。

## 四、DeepSeek 侧事实核对

### 4.1 模型

| 模型名 | 版本 | 上下文 | 最大输出 | JSON Output | Tool Calls |
| --- | --- | --- | --- | --- | --- |
| `deepseek-flash` | DeepSeek-V4.1-Flash-1017 | 1M | 384K | 支持 | 支持 |
| `deepseek-v4-pro` | DeepSeek-V4-Pro-0813 | 1M | 384K | 支持 | 支持 |

旧名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍可调用但已下线，按 Flash 计费。本项目只提供上表两个模型名。

### 4.2 价格（元 / 百万 token，官方定价页）

| 模型 | 输入（缓存命中）空闲 / 高峰 | 输入（未命中）空闲 / 高峰 | 输出 空闲 / 高峰 |
| --- | --- | --- | --- |
| deepseek-flash | 0.02 / 0.04 | 1 / 2 | 4 / 8 |
| deepseek-v4-pro | 0.15 / 0.30 | 4.5 / 9 | 13.5 / 27 |

高峰定义为北京时间周一至周五 9:00–12:00、14:00–18:00（不含法定节假日）。前端按当前时段估算，节假日无法判断，已在 UI 说明。

Search / Fetch：每 1000 次成功请求 5 元，失败或空结果不计费。

### 4.3 调用细节

- 思考模式默认**开启**，关闭需 `{"thinking":{"type":"disabled"}}`；开启时 `temperature` / `presence_penalty` / `frequency_penalty` 不生效（传了也不报错）。本项目默认关闭思考以便用 temperature 控文风；开启时按官方建议带 `reasoning_effort: "high"`。
- JSON 模式：`response_format: {"type":"json_object"}`，且 **prompt 里必须出现 "json" 字样并给出结构示例**，否则可能不生效或返回空 content。本项目每个结构化模板都写明 JSON 结构与字段。
- 流式：`stream: true` + `stream_options: {include_usage: true}` 才能在最后拿到 usage；本项目据此做费用核算。
- Search 工具：`POST https://api.deepseek.com/v1/tools/search`，`{query, count(1–50), need_content}`，返回 `results[]`（`title/url/summary/snippet/authority/date`）。限速 100 QPS；`count` 不影响单价。
- Fetch 工具：`POST /v1/tools/fetch`，`{url}` → `{title, content}`，限速 25 QPS，且按目标域名另有 QPS 限制。

### 4.4 错误码

`400` 格式错误 / `401` 认证失败 / `402` 余额不足 / `422` 参数错误 / `429` 限流 / `500` 服务故障 / `503` 服务繁忙。
其中 429、5xx 可安全重试；401/402/422 重试无意义；正文阶段重试会重新计费，UI 明确标注。

## 五、中继的最小设计

仅在直连失败时启用，`app/worker/maimemo-relay.js`：

- 只接受 `/maimemo/api/v1/memo/**`，其余路径 403；
- 只允许 `GET` / `POST`，必须带 `Bearer`，否则 401；
- 来源白名单 `ALLOWED_ORIGIN`，默认示例值，不是通配；
- 原样转发 `Authorization` 与 body，回写状态码与 body，补 `Access-Control-Allow-*`；
- 不解析业务字段、不写日志、不落库、不缓存（`Cache-Control: no-store`）；
- 上游不可达返回 502 并带错误说明。

它不承担任何业务逻辑，也不做任意 URL 代理，因此不会成为开放代理或数据中转站。

## 六、结论

1. **DeepSeek 浏览器直连成立**，含错误响应，无需中继。
2. **墨墨 OIDC 端点在浏览器里可用**（含错误路径），PKCE 公开客户端可行。
3. **墨墨数据接口预检放行，但错误响应不回 CORS 头**，个人 Token 模式下前端无法区分错误类型；官方还声明只有审核通过的应用域名才被允许跨域。因此「直连优先 + 可选最小中继」是当前最诚实、最可用的架构。
4. 数据接口仍是公测，字段与可用性可能变化：代码里所有字段都按可选处理，缺失时降级而不是崩溃。
